# BetterLitematica

面向 Minecraft Fabric 的独立投影与建造辅助模组，集成投影查看、编辑、材料统计和打印功能，不依赖 Litematica 或 MaLiLib。当前版本为 **0.4.13**。

## 核心功能

- **投影管理**：加载多个投影，独立移动、旋转、镜像，按层或方块类型过滤显示。
- **建造辅助**：创造／生存打印、简单放置、创造粘贴，以及容器填充等施工工具。
- **实时待建列表**：显示施工范围内尚未完成的投影方块，暂停打印时继续更新；每行四项，自动换行，不扣除背包材料。
- **选区与编辑**：选区保存、三轴拖动、投影编辑与项目版本管理。
- **材料与校验**：完整投影材料统计、世界差异检查，以及方块和容器信息查看。
- **统一界面**：瓷白／曜石双主题、快捷轮盘、自定义快捷键和展开动画。

## 默认操作

| 操作 | 默认按键 |
| --- | --- |
| 主菜单 | `M` |
| 快捷轮盘（同时保留玩家列表） | 按住 `Tab` |
| 施工总开关：开始／暂停当前启用的模式 | `Caps Lock` |
| 停止打印 | `Ctrl + Caps Lock` |
| 总投影渲染开关 | `M + R` |
| 打印机设置 | `M + B` |

组合键先按住 `M` 再按另一键。已有配置和自定义按键会保留，以“设置与快捷键”显示的绑定为准。

- 方块过滤：投影行的配置 → 方块显示，选择黑名单或白名单后勾选投影内方块；搜索可用名称或 ID，“全选搜索结果”仅作用于当前搜索结果，最后点“保存”。未保存返回会要求再次确认。
- 简单放置：开启“简单放置”和“按住连续”，按住右键扫过投影即可连续放置，左键保持正常挖掘。不同位置没有统一冷却，同一位置短暂等待确认；松开即停止。
- 预览：左键拖动旋转，中键拖动平移，滚轮缩放，双击或复位按钮恢复视角。预览左上角显示尺寸、包围盒总体积格数和非空气方块总数；摆放旋转后尺寸方向同步变化。
- 在加载列表中悬停文件即可预览，无需选中或加载。另存为 `.litematic` 时默认附带缩略图和旋转预览缓存，也可关闭“附带预览”；普通 Litematica 与 litematica-printer 能读取同一文件。缓存校验失败会重新生成，不影响方块数据。
- 支持共享投影文件夹：在“加载投影 → 文件夹 → 加载文件夹”中使用系统文件夹选择窗口选择目录（Windows 使用原生文件管理器）。每个目录显示为一行路径，重启后仍会保留；外部目录右侧的删除图标只取消加载目录，不删除文件，本实例目录不可移除。可加载其他版本实例的 `schematics`，支持预览、加载和重新加载；读取能力仍取决于投影格式与当前游戏的方块注册表。外部投影另存到本实例的 `schematics` 中。
- 加载投影页在搜索框右侧提供“加载文件”图标：使用系统文件选择窗口打开单个 `.litematic`、`.schem`、`.schematic` 或 `.nbt`，复制到本实例的 `schematics` 后加载。原文件和内嵌预览保持不变，同名文件自动添加编号，不覆盖已有投影；选择默认目录里已有的文件时直接加载。
- 全部支持版本均提供跨版本兼容加载：高版本 `.litematic` 保留可识别的文件结构时会尝试读取，当前游戏不存在的方块或状态直接跳过。投影列表名称前显示琥珀色感叹号，悬停可查看“不兼容的投影”与跳过种类数；这些位置不参与显示、校验或施工，也不会被当成空气挖掉。原文件保持不变；损坏的文件或无法识别的新结构仍会拒绝加载。已实测将 26.3 世界导出的投影加载到 1.20.1，支持的旧方块能够打印，新方块位置不参与施工。
- “周围待建 HUD”对新配置默认关闭，开启后即使停止打印也持续更新，统计所有未完成位置，不扣除背包。橙框表示含错误方块或状态；溢出不自动翻页，按住轮盘键、悬停卡片后滚轮翻页。已有开启偏好不变。
- 打印徽章显示范围内已匹配位置的百分比与细进度环，每 200 ms 更新；未加载位置不计入分母。缺料、确认延迟、超出高度或待加载持续约 1 秒后，徽章显示对应原因。
- 缺料只由实际取料失败产生，与待建列表合在一张卡片：缺料行优先显示图标、名称和范围需求，最多六行，并按可用高度收紧；整张卡片最多占屏幕安全区高度的 45%，其余待建方块仍为每行四格。红框表示没有已确认可用的材料，橙框表示方块或状态需修正。库存恢复或需求消失后，经两轮核对移除缺料记录；关闭“周围待建 HUD”仍保留必要缺料提示。
- 库存核对包含背包和已开启补给来源的潜影盒。策略页选择“补给：自动”可检测服务器的 Quick Shulker 通道，也可手动选择其他潜影盒协议；服务器权限和同步结果决定能否取到。
- 每个施工模式、轮换模式及全部关闭均可单独绑定，新增绑定默认留空；切换后动作栏提示当前模式，按 `Caps Lock` 开始／暂停。`Tab` 保留轮盘与玩家列表。
- 设置页的“搜索全部设置”和打印机的“搜索设置”可按名称、说明或拼音定位选项。方块过滤、打印名单和破基岩允许名单支持名称、ID、全拼及首字母，例如 `玻璃`、`boli`、`bl`；多音字也可匹配，`chongsheng` 或 `csm` 可找到重生锚。拼音表随模组离线提供，来源及许可保留于资源内。
- 设置悬停可查看说明；父功能关闭时相关子项灰显。打印机与破基岩页可“保存并返回”，也可直接“保存并开始”／“保存并启动队列”。设置值输入框回车提交；搜索框回车不会保存或关闭。右下角无改动显示“返回”，有改动显示“放弃”，再次确认才丢弃草稿，Esc 行为相同。
- 提供“问题反馈”，入口位于模组主菜单左下角、游戏标题画面右上角。无需论坛账号；版本与运行环境自动附带，日志和崩溃报告默认勾选，可关闭并查看清理后的内容。识别出的玩家名、系统用户名、聊天、密钥、地址和个人路径会清理；问题描述和联系方式按你填写的内容提交，请先检查预览。
- 闪退后重新启动、尚未进入世界时，反馈使用上次运行日志；本次已进入过世界则使用本次日志。只附带对应运行期间的崩溃报告，也支持 JVM 崩溃日志；旧报告或无法确认时间的报告不会附带，并提示日期。草稿会保留，超时重试复用原提交标识；成功后可复制报告编号、查询处理状态。反馈发送至项目服务 [forum.imax9d.dpdns.org](https://forum.imax9d.dpdns.org)，仅在手动点击提交后上传。
- 破基岩：施工页开启“破基岩”，默认按“选区”范围工作，选好区域后按 `Caps Lock` 即可，无需加载投影；范围改为“投影”时仅移除与投影不符的基岩。需要生存模式、至少两个普通活塞、红石火把及足够的实际破坏能力，不限定镐、附魔、效果等级或固定剩余耐久；需要临时支撑时携带黏液块，靠近目标并留出施工空间。
- 破基岩默认按实际速度自动选择可用物品。若其他模组或高等级药水效果导致客户端低估速度，可在“破基岩设置 → 常规”开启“手持工具兼容”，保存后拿好要用的物品再启动，也支持空手。兼容模式保留该栏位并允许能量、耐久等数据正常变化；成功仍需服务器确认，失败会停止，材料回收超时会提示手动清理。
- 独立破基岩队列与打印机的破基岩模式互斥。切换只暂停另一方并保留独立队列；只有“清空独立队列”会丢弃目标。设置页可以启动队列，返回游戏后才施工。

## 与其他模组共存

本模组会接管下面的功能，不会改写它们的配置文件；移除 BetterLitematica 后接管解除。

| 模组 | 接管内容 |
| --- | --- |
| Litematica | 投影渲染、键盘鼠标输入、快捷键、简易放置 |
| litematica-printer | 打印逻辑和打印快捷键 |
| Tweakeroo | 与施工冲突的放置、自动点击和换物品功能，见下文 |

首次进入世界检测到这些模组时，会在聊天栏提示一次；“设置与快捷键 → 交互设置 → 模组共存”可随时查看。Tweakeroo 拦截仅在打印运行、独立破基岩启用或本模组执行放置动作时生效，停止／暂停后恢复其原设置；普通手动游玩不会全时关闭这些功能。

临时拦截项：精确／灵活／快速放置、放置网格与限制、假潜行放置、放置后点击、放置前取块、手持补货、自动换工具，以及快速／按住／周期点击。对应配置键：`TWEAK_ACCURATE_BLOCK_PLACEMENT`、`TWEAK_AFTER_CLICKER`、`TWEAK_FAKE_SNEAK_PLACEMENT`、`TWEAK_FAST_BLOCK_PLACEMENT`、`TWEAK_FAST_LEFT_CLICK`、`TWEAK_FAST_RIGHT_CLICK`、`TWEAK_FLEXIBLE_BLOCK_PLACEMENT`、`TWEAK_HOLD_USE`、`TWEAK_PERIODIC_USE`、`TWEAK_PERIODIC_HOLD_USE`、`TWEAK_PLACEMENT_GRID`、`TWEAK_PLACEMENT_LIMIT`、`TWEAK_PLACEMENT_RESTRICTION`、`TWEAK_PLACEMENT_REST_FIRST`、`TWEAK_PLACEMENT_REST_HAND`、`TWEAK_PICK_BEFORE_PLACE`、`TWEAK_HAND_RESTOCK`、`TWEAK_TOOL_SWITCH`。

做超大投影时建议安装 Sodium，由它负责地形渲染，本模组负责投影；两者可以同时使用。

1.20.1 的当前开发构建提供独立实现的原生地形管线：专用后台线程构建网格，多个区块共用区域缓冲，按区域批量绘制，上传按时间预算分段进行。空区块不预先创建显卡缓冲；旧缓冲等显卡用完后再回收。透明方块保留原有排序，位置变化、世界切换和资源重载会丢弃过期结果。

原版地形的可见区块遍历也已替换：按六个面的连通关系向外搜索，提前检查视距与视野，复用保守的候选列表；未知区段允许通过，开洞或前方区块加载立即刷新。仅封闭视线时，最多保留 200 ms 的额外候选后合并清理，方块本身仍立即显示并正常遮挡后方。没有沿用历史实验的主轴角度裁剪。模型、流体、光照及资源包着色器仍通过 Minecraft 的渲染接口生成和绘制；这不等同于重写 Sodium 的全部功能。

启动器 JVM 参数 `-Dbetterlitematica.disableTerrainOptimizations=true` 可禁止加载全部地形钩子，需重启；投影自身的后台构建和缓存仍然保留。检测到 Sodium、Iris、Canvas、VulkanMod 或 OptiFabric 时自动跳过这些钩子。不捆绑 Sodium，不改写其他模组配置，历史参考算法的来源及许可见 [第三方说明](THIRD_PARTY_NOTICES.md)。

Sodium 组合已有真实路线数据；Iris、Canvas、VulkanMod、OptiFabric 尚未做完整游戏验证。跳过地形 Mixin 仅说明没有加载这些钩子，不等于整个模组兼容性已通过。

## 源码结构与构建

1.20.1 渲染审查版本的实测结果见 [星空树投影性能对照](docs/performance/2026-10-11-1.20.1/README.md)，包含两个高度的折线图、逐帧数据、早期回退记录和测量限制。后续 [帧时间尖峰优化复测](docs/performance/2026-10-12-1.20.1/README.md) 记录了 review.7 的长帧改善与仍未消除的尖峰。

`core/` 提供数据模型与算法，`blueprint-io/` 负责投影读写，`runtime/` 负责缓存与后台调度；`fabric-1.20.1/`、`fabric-official/` 和 `versions/` 负责各游戏版本的适配。

[原版渲染器下的投影性能](docs/performance/2026-10-12-vanilla-renderer/README.md) 记录了 review.16 的逐帧实测：原版渲染器下平均帧率明显提高，但长帧增多，密集投影视角仍需改善。这些数字不能沿用为后续修复版本的性能。

[地形安全边界与尖峰复查](docs/performance/2026-10-12-terrain-risk/README.md) 记录了 review.21 的默认关闭策略、旧长帧数据对齐和投影暂存数组复用验证；尚未重新进行游戏性能验收。

[地形钩子逐项复查](docs/performance/2026-10-12-terrain-hooks/README.md) 保留 review.22 阶段的记录；[遍历钩子修复](docs/performance/2026-10-13-terrain-repair/README.md) 记录了 review.23 修复并恢复第 8 个钩子后的原版对照与局部性能验证。局部微基准不是整场帧率或帧时间尖峰结论。

[原生地形管线说明](docs/performance/2026-10-13-independent-terrain/README.md) 保留 review.24 的实现范围与当时未做最终游戏验证的记录。后续替换可见区块遍历的实现、1080p 路线实测及逐帧数据见 [可见区块遍历与 Sodium 对照](docs/performance/2026-10-13-visibility/README.md)。

构建需要 **JDK 25 或更高版本**。Windows 使用 `./scripts/build.ps1`，Linux/macOS 使用 `bash scripts/build.sh`，默认构建 1.20.1；指定其他版本时追加任务，例如 `:fabric-1.21.11:build`。全部版本分别使用 `-AllVersions` 或 `--all`。

核心回归检查位于 `core/src/test/java`，运行 `bash scripts/build.sh :core:selfTest`（Windows 可用 `./scripts/build.ps1 :core:selfTest`）。CI 单独执行这些检查，失败会使流水线失败；测试代码不打入模组 JAR。每个游戏版本的构建还会检查设置 ID、说明、控件绑定、停止原因和连续放置节奏，避免适配后遗漏功能。声明了临时审查版本时，`review/` 分支仅构建这些版本；正式推广后执行完整版本矩阵。

0.4.8 已完成全部 31 个目标的本地构建、实际采用源码及 JAR 内容检查，核心回归通过 136 项、2,467,474 条断言。跨版本功能此前已在真实 26.3 导出、1.20.1 加载与施工流程中验证，并检查两种主题的兼容警告；本轮推广未逐一启动其他游戏版本，构建通过不等于所有运行环境均已验收。
