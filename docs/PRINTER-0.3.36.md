# 打印吞吐与已完成位置显示

2026-09-22，Minecraft 1.20.1 / Fabric，沿用独立实现。

## 三项 0 仍慢的原因与处理

0.3.35 的数量、间隔、位置冷却均可关闭，但仍有固定 1 ms 施工预算、搜索结果跨 tick、创造取料等待及临时失败的 20 tick 退避。用户本次明确测试环境是单人创造。

- 单人内置服务器的创造取料沿用原版取物顺序：本地快捷栏更新、普通创造物品包、选槽同步、施工。新材料可在同一 tick 使用；只有打印机且无在途事务、玩家背包界面、保护格准入及物品特性允许时使用此路径。生存背包交换和多人创造仍等待真实库存回执。
- 空施工队列直接分类已取得的至多 512 格数字快照，当 tick 入队执行；耗尽后可在同一预算内补页。有可施工队列时继续后台预取，不等待尚未完成的 Future。
- 性能页新增工作预算，默认 8 ms，可设 1–16 ms。采样、补页和施工共用同一截止时间，每 tick 另有 8 页扫描、4096 次尝试上限；非零数量限额仍正常执行。原版 API 和单个步骤不可抢占，不能承诺绝对不超过设置时间。
- 每 tick 取得一次源查询视图并收取解码结果；不再每格收取、重复创建源查询对象。未加载源区段仍保持未知。
- 放置预测保留最多 256 种状态的最近可用方向提示。每次仍重新验证距离、上下文、碰撞、状态和支撑；场景改变时回退完整搜索。属性排序和编码位宽复用不可变缓存，没有改变协议。
- 本地准确放置的 128 项在途容量满时暂让执行，不再把未发送动作误当失败并冷却一秒。无支撑、暂不可放置面等转为次 tick 重试；队列和预算阻止立即自旋。
- 没有角度变化的放置不发送重复的转头及恢复包。材料分组和快捷栏保留继续生效。

每个快捷栏格保留最新发送的创造物品独立副本。旧 S2C 回包让本地显示与最新意图冲突时，在两条直接就绪路径先发送普通创造物品包重申，不屏蔽回包或伪造确认；记录不因同物品回包而清除，避免 A→B→A 时序问题。

以上是实现变化；无窗口检查不能换算成实际每秒方块数或 FPS。

## 已完成位置

客户端世界中的方块与投影变换后的完整方块状态一致时，该格不再生成投影网格，包含普通模型、流体、方块实体模型和光源标记。错误状态继续显示；拆除或改变后恢复。未加载区块不视为已完成。材料统计、源文件和打印目标不因此删减。

世界方块更新、区块加载和卸载合并为有限的世界区段通知，不依赖材料分析。渲染端只标记受影响网格；在建期间收到的新变化会保留到下一轮刷新。旧网格在新网格完整准入前保留，避免先删网格产生大片空白。

世界通知最多保留 2048 个区段，每帧处理至多 64 个；溢出转为惰性全局失效，不无限积累事件或逐格扫描整份投影。总顶点资源仍限 1 GiB / 65536 个对象，内部预留 8 MiB / 8192 个对象 / 1 个网格组给替换构建；旧资源退休后实际释放前继续计费。网格净增长或极端单网格对象数量超过预留空间时仍可能等待资源释放。
