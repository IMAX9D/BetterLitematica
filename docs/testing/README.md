## 性能测试的主要结果

1.20.1 的 0.4.14 星空树持续打印，最高档 0/0/0、65% 高度：BetterLitematica 平均 **623.7 FPS**，Litematica＋Printer 为 **34.7 FPS**，Litematica＋Printer＋Sodium 为 **256.2 FPS**。Better＋Sodium 的 1% low 为 **84.1 FPS**，高于 Better 原生的 **60.8 FPS**。完整表、中央区域与显卡负载均在对应报告中。

1.21.1 的 0.4.14 测试暴露了尚未完整适配的性能差距：65% 高度原生 Better 为 **67.4 FPS**，Better＋Sodium 为 **101.4 FPS**。随后继续推广投影和地形实现，而不是沿用这一轮状态作为最终版本。

1.21.1 的 0.4.15 → 0.4.16 同路线复测，65% 高度从 **251.56 → 701.86 FPS**，1% low 从 **28.50 → 67.37 FPS**；40% 高度从 **221.76 → 549.35 FPS**，1% low 从 **29.11 → 61.35 FPS**。对应 >50 ms 长帧数从 **24/19 → 0/0**。40% 新版主表采用用户指定的整趟复测，第一次 369 ms 尖峰记录也保留。

这些性能数字的被测版本、硬件与场景写在各自报告中；0.4.17 此次做的是全版本构建与功能回归，没有把旧性能数字改标成新版成绩。

## 用户实际遇到的问题与修复

| 问题 | 定位与处理 | 验证 |
| --- | --- | --- |
| 打印自动暂停 | 诊断调用栈确认 IPN 自动补充冲突，独立 backpack 包仅在打印期间暂缓它 | 用户反馈暂停问题消失；实际 Mixin 挂接检查 |
| 用多少取多少，补货频繁 | 改为按可用槽位批量备货、有限 FIFO 轮换，积累空槽后补满 | 78,493 条库存策略检查、2,799 条批次检查；100 手长等大量材料候选在模型中覆盖 |
| 背包满，垃圾桶补货中断 | 保留物品保护和服务端双确认；修正 Fabric 提前取消导致回包观察器未执行 | 9 个真实垃圾桶编解码检查、8 个 Mixin 目标/13 个处理器、联合 Fabric 回包链 |
| 教堂加载报 NBT allocation budget exceeded | 原 512 MiB 限制不足；正式版按最大堆的 60% 生成读取预算，可配置 1–90% | 实际 JVM 堆与配置检查；完整导入 501,396,805 格、31,681,915 个非空气方块、3,999 个方块实体、35 个实体 |
| 大文件预览失败 | 初次、旋转和精细预览统一使用共享读取器 | 原教堂基础和精细预览均生成，源文件哈希未改变 |
| 分层边界残面 | 在片元着色器中区分边界面属于哪一层 | 五种资源接口在实际显卡上共通过 665 条检查 |
| 普通缺料导致施工退出 | 有料优先的有限材料批次；潜影盒无料回到调度并记录缺料 | 核心队列回归与全部适配的编译调用检查 |
| 编辑器 HUD 显示旧目标或旧方块 | 跟随实际编辑目标、固定方块与编辑状态 | 全部适配的最终源码/编译调用检查 |

backpack 仍是独立 1.20.1 兼容包；其协议和策略源码与此前 full-stock.5 保持一致，仅更新 0.4.17 版本兼容。
