# 下一轮验收清单

## A. 构建

- JDK 17 Windows：`scripts/test-core.ps1`，保存完整输出。
- `scripts/build.ps1` 成功，记录 Java/Gradle/Fabric 精确版本与产物 SHA-256。
- 不允许用删掉模型渲染代码、删除难测能力或者扩大版本范围的方式制造“通过”。

## B. 开发世界基本闭环

新建测试世界，使用 `examples/demo.litematic` / `demo.schem`。

- M 菜单、投影路径、加载/取消/卸载、移动到玩家坐标。
- 石头、玻璃、楼梯真实模型和纹理可见，无全屏状态污染。
- 坐标输入、90° 四向旋转、X/Z 镜像组合，方块状态与位置一致。
- X/Y/Z 单层与区间切片，暴露的截面正确。
- 超出显示预算时有明确状态，不把截断视为加载完成全部可见。
- 重复切换投影 100 次、取消 100 次、世界切换、退出、F3+T 后无旧结果挂回、无崩溃。
- 调试输出正确显示未知模型/数据版本不匹配/格式错误，而不是静默丢失。

## C. 正确性扩展

真实来源文件：Litematica v5/v6、Sponge v2/v3，负尺寸、多子区域、不同偏移、稀疏/密集/复杂调色板。重叠区域目前应明确拒绝。将导入各坐标的预期状态同独立参考比对。加入旧版本和模组缺失的真实文件，不能随意转换空气。

扩展模型之前先决定：只读世界视图如何提供邻居/生物群系、模型 API 何处线程安全、透明排序目标、流体网格与实体处理。不要把所有特殊内容替换为立方体后宣布功能对齐。

## D. 性能对照

同硬件、同 MC/资源包/显示距离、同可见内容、同移动路线，对比基线与新实现。关闭 UI 自动刷新等噪音并预热，再记录多次冷导入和暖加载。

分别记录点击后 UI 可响应、首次可见、当前视野完整、全部缓存建立的时间；帧耗时 P50/P95/P99/最大值；内存 RSS/堆/直接内存/实际 GPU 资源；任务队列与缓存压力；取消延迟；长时间开关后的回落。

禁止只比较平均 FPS；禁止新实现只画 96 个 Section、旧实现画全建筑，却声称同等工作量获得提升。巨大稀疏、密集实心、透明建筑、复杂红石、模型资源包分别报告。

## E. 发布范围

先发布实证支持的 Fabric 1.20.1。选择第二个实际接口有差异的版本做适配，检验核心依赖隔离。旧 JVM/Forge/NeoForge 分别评估；没有逐版本 CI 和烟测，不使用“全版本已支持”。
