# 材料统计与渐进校验 · 0.3.14

## 数据完整性

附近 512 区段是渲染候选/网格缓存上限，不是源文件计数范围。SchematicImporter 遍历全部子区域的所有实际格，写入 BPC 全局方块状态直方图；全空气区段省略存储，但其格子仍参与计数。导入结束后才提交缓存，BlueprintCache.open 检查直方图总和等于全部区域体积。材料汇总读取该完整直方图，不读取当前可见网格、已解码区段或游戏世界。

材料列表自动汇总选中投影的完整材料（不按显示分层裁剪），每 tick 最多解析 256 个调色板状态、预算 2 ms。半砖、门上下部等沿用物品成本映射；无法识别的状态单独显示数量，不能当作零需求。背包只用于比较已有和缺料，缺料是完整需求减背包数量，不代表施工现场尚缺方块。导出及 HUD 使用同一数据源。大调色板的汇总允许逐批显示，CSV 在汇总结束后启用。

完整方块计数不等于无损保存原始文件的所有 NBT、实体和计划刻；缓存仍不能替代源文件用于完整导出。物品成本映射仍有模组方块/特殊方块边界，不宣称所有物品需求语义均已覆盖。

## 世界校验

校验单独启动，使用当前分层。按 16³ 区段延迟生成任务；队列最多 32768 个位图任务（位图负载约 16 MiB，另有对象开销），满时暂停新任务生成，不丢弃后续区域。超出容量且前部长期不加载时，后部发现会延迟。

全区段未加载时延迟重试，部分加载时已完成格用位图标记；重试不重复累计结果。解码未就绪只让当前任务等待，不阻塞其他区段；每次区段处理只获取一次解码结果，减少逐格缓存查询。当前优先完成已开始的区段，避免解码缓存反复淘汰。世界读取仍只在客户端主线程，每 tick 最多 16384 次格处理、3 ms 时间预算，实际数量取决于负载。

未加载区块保持待处理，不写成空气或永久 UNKNOWN；客户端运行时轮询其加载状态（单项至少间隔 20 tick，队列大时更久）。未知方块状态仍单独统计 UNKNOWN。已扫描结果立即加入报告，界面每 10 tick 更新，高亮仍需手动开启。完成过的格是扫描时快照，不会持续重扫已发生的世界修改；需要新的现场结果时重新校验。

取消保留已有结果并释放待处理队列。移动、分层变化、重载/移除及世界切换沿用取消路径，不继续使用失效扫描任务。

## 验证

- 60 项核心测试，335,987 次断言；48 项真实 Minecraft 无窗口检查。
- 新增跨 563 个区段的 9000 格独立导入样本：超过预览 512 区段上限，直方图仍精确包含全部 9000 格。
- 千万格合成直方图在没有世界或渲染器的条件下完成物品汇总；验证双半砖计数、门上半部去重和未知状态保留。
- 队列测试覆盖延迟重试、不阻塞后续任务、已完成位图保留、不重复完成、边缘区段和容量限制/取消。
- 未启动游戏。没有实测游戏 FPS、真实千万格扫描耗时、区块加载事件或实际动态高亮；上述调度预算不是实测加速倍数。
