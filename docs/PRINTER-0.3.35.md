# 打印机节奏与换料修正

2026-09-22，独立实现，Minecraft 1.20.1 / Fabric。行为核对沿用 `PRINTER-PARITY.md` 中固定的参考提交；没有引入新的服务端协议。

## 设置生效

施工页的三项数值通过保存、返回、Esc、开始/继续统一提交。非法输入保留在原框内并阻止提交；切页保留草稿。配置未变时不重置工作队列；世界切换后的旧页面不能写回。

| 设置 | 执行含义 |
|---|---|
| 批次间隔 / tick | 按成功进入发送阶段的批次计时；0、1 均可每 tick 执行，2 为每 2 tick 一批。同批次内可执行多次交互 |
| 每 tick 上限 | 1–256 为实际交互上限；0 取消数量上限，仍受约 1 ms 执行时间、有限队列和尝试预算约束 |
| 位置冷却 / tick | 发送交互后，该位置在期限前不重复开始；0 关闭。执行前再次检查，不再只在候选入队时过滤 |

上限不是保证速度。缺料、不可施工面、服务器回执及单次原版 API 耗时仍会影响实际吞吐。失败候选另有重试退避；进行中的挖掘和破冰续作保留所有权并遵守批次及破坏预算，不作为新位置操作重复开始。移动仅重建搜索，不清除位置冷却或已开始的施工步骤；续作仍检查当前位置的范围和世界状态。

已发出放冰、挖掘等交互但仍在等待后续步骤时，照常扣除限额；仅等待库存确认时不扣除。冷却表达到 8192 项时等待过期回收，不丢弃尚有效的记录。外部矿工内部执行仍由已有外部模组控制，不能宣称本地限额限制其全部内部操作。

## 减少换手

- 按实际材料物品分组，同一物品的不同方块朝向共用一组，优先继续手持材料。
- 连续处理 64 个候选后让其他材料获得机会，避免长期饿死依赖步骤。
- 在选料前检查放置面和支撑，减少对无法施工位置的无效换手。
- 打印机补入材料时优先使用未保护的空快捷栏格，保留此前材料供之后直接切换。满栏才回退原选格策略；普通取料与简单放置仍用原有目标格策略。
- 快捷栏切换使用原版选槽同步和原版缓存，可在同一 tick 继续交互。背包交换、创造取料继续等待真实库存回执，不虚构确认、不盲目重发。
- 去皮、锄地和堆肥优先保留当前符合条件的物品；空或无效堆肥清单不会触发空手交互。

核心调度用例中，128 个交替排列的两种材料从旧轮转的 127 次切换减少为 1 次；测试同时覆盖不同朝向、候选去重和公平性。这是固定输入的队列检查，不是实际服务器上的换手次数或吞吐测量。

## 验证边界

新增自动检查覆盖批次间隔、同 tick 限额、不受旧 32 次尝试截断、0 值语义、等待步骤计费、冷却过期与满容量、移动范围、设置保存、材料保留及保护格。两个独立验收角色复核了设置与调度接线。

完整构建还发现并修复草稿保存完成通知早于资源记账释放的时序问题；确定性回归检查见 `DraftRecoveryChecks`，与打印机参数无关。

本轮未启动 Minecraft。真实界面操作、高延迟服务器的换料回执、移动中的挖掘与冰水续作，以及实际吞吐仍需玩家验收。最终测试数和产物摘要见 [验证记录](../VALIDATION.md)。
