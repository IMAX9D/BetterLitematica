# 0.3.1 渲染修复与千万方块压力样本

## 实现

旧管线对每个投影表面直接做透明混合，不写深度；同一像素内多层面、相邻玻璃面、区段边界面和重复摆放会累计颜色。新管线为所有摆放共用一个有颜色/深度的缓冲，复制真实世界深度，渲染投影最近可见表面，最后统一按用户透明度合成一次。只对投影绘制施加小幅 polygon offset，避免与真实世界共面时争夺深度；不修改世界坐标或原始数据。

这是一种最近表面的施工投影显示策略，不是多层真实玻璃的物理透明效果。流体、BER、FRAPI 等既有缺失仍存在。OpenGL 路径目前编译通过，尚未游戏内目视或 GPU 测量。

构建区段前等待六个相邻区段解码并持有引用，缺失数据不临时当空气。跨区段内部面、原版判定可隐藏的同类玻璃面不再输出；完全包围的格子跳过模型取样。分层切口保留。仍未合成不同子区域之间的相邻面。

缓存采用可见工作集保护：容量不足时停止构建新网格，不淘汰仍在视野里的网格后下一帧重建。视野/候选集合改变才重新准入。同源哈希与变换相同的摆放只绘制一次，不删除摆放。

附近候选上限 512 区段，查询半径 192 格。每摆放 CPU 解码 8 MiB、网格逻辑预算 128 MiB、活动区段 8 MiB；8 个摆放最坏网格逻辑预算约 1 GiB，按需分配而非预分配。合成缓冲另占用随窗口像素数增长的颜色/深度空间。网格每批最多 16384 顶点，仍受每帧上传 512 KiB、构建约 1.5 ms / 2048 格的协作限制。预算满时会延后显示，因此不声称整张千万方块投影同时全量渲染。
