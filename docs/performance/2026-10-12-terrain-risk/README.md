# 地形安全边界与尖峰复查

2026-10-12，Minecraft 1.20.1，构建 `0.4.4-review.21`。本轮没有重新运行飞行路线，不能宣称尖峰已经解决，也没有新增 Iris / Canvas 的游戏兼容性结论。

## 默认路径

`review.16` 引入的地形遍历、视锥复用、非空区段索引及其辅助访问器，共 8 个地形 Mixin，从本构建起全部默认不加载。普通启动沿用游戏或外部渲染器的地形判定；投影自身的后台构建、模型缓存仍保留。

`-Dbetterlitematica.experimentalTerrainOptimizations=true` 仅供显式选择实验路径。原有 `-Dbetterlitematica.disableTerrainOptimizations=true` 优先禁止加载。Sodium / Iris / Canvas / VulkanMod / OptiFabric 的避让继续生效。

该调整收紧了风险范围，并没有证明实验算法已经可靠。此前的平均帧率收益来自开启地形改写的路径，不再代表新版默认配置；默认配置的实际帧率需要重新测量。检测到其他渲染器就跳过，也不能代替其投影、光影与界面的实际兼容性验证。

## 旧逐帧数据复查

以下来自 [review.16 的原始路线](../2026-10-12-vanilla-renderer/README.md)，没有重新采样。`interval_ns` 表示进入当前帧之前的间隔，因此使用上一行的投影工作计时进行对齐。

| 原生路线高度 | 超过 50ms 的帧 | 其中投影计时小于 10ms | 与 GC 增长窗口重叠 |
| --- | ---: | ---: | ---: |
| 65% | 25 | 20 | 25 |
| 40% | 22 | 19 | 21 |

两轮合计 47 次长帧，39 次不能仅由投影的准备、构建、绘制计时解释。46 次与 GC 增长窗口重叠，但 GC 只有约 1 秒一次的累计采样；普通窗口中也分别有 63/87、64/87 出现 GC，因此这只是相关性线索，不是逐帧因果结论。投影墙钟计时本身也可能包含 JVM 暂停。

独立 R14 诊断轮曾采样到大量世界区块保存和光照数组分配，也采样到本模组 `RenderedCells.Builder` 的暂存数组。前者不能通过改写可见区块遍历解决；本轮仅针对在现有源码中仍存在的后者做局部修改。

逐帧对齐明细见 [existing-spikes.json](existing-spikes.json)。

## 本模组的局部修改

投影区段构建的 4096 项状态暂存数组改为有上限的复用池。每个结果从后台计算、等待上传到补充方块实体数据期间始终独占缓冲区；成功消费、取消、丢弃都归还，重复释放不会重复归还。重新借出时清空，已发布到网格的是独立的不可变快照。

池最多保留 `MAX_IN_FLIGHT` 个缓冲区，本机为 12 个，状态数组部分约 192 KiB。没有修改原版世界保存或光照逻辑，也没有新增原版地形 Mixin。

同一 Java 17 环境下，用生产 JAR 的实际类做隔离分配测量：预热 2000 次，测量 20000 次结果创建与释放，旧版 review.20 每次约 **18355 字节**，新版 review.21 约 **1936 字节**。这证明该路径减少了临时分配，不代表整场游戏分配减少同样比例，更不等于帧时间尖峰已经改善。

## 验证边界

- 构建通过；构建自带的 1014 项连续放置检查和设置完整性检查通过。
- 使用 Fabric Loader 0.18.4 加载生产 JAR，逐个检查这 8 个 Mixin 的目标类：新版默认均未注入；显式实验开关时均注入；禁止开关优先；安装真实 Sodium 0.5.13 后，默认和显式实验两种配置均未注入。
- 结果生命周期检查覆盖重复释放、两个存活结果不共享缓冲区、借出后无旧状态、已发布快照不被复用改写。
- 类加载与分配检查不会启动游戏，不构成地形、光影或界面的视觉验收。Iris、Canvas、VulkanMod、OptiFabric 未做游戏实测。
- 保留上一轮左下工具卡修复，仅修改 1.20.1 审查层，未推广其他版本。

实验地形路径恢复默认前，至少需要同一存档下的连续转向、穿越遮挡边界、区块装卸与重建、传送换维度、资源重载对照，以及 Iris 开关光影和 Canvas 的实际画面验证。尖峰验收应继续使用 P99、1% Low 和超过 33/50ms 的帧数，不能只比较平均 FPS。

构建及检查记录见 [validation.json](validation.json)。
