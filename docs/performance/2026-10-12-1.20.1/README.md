## 条件与口径

- i5-13600KF、RTX 3080 10 GiB；Java 17.0.20.1、4 GiB 堆上限；Fabric Loader 0.18.4、Fabric API 0.92.2+1.20.1。
- 星空树投影高度 580；65% / 40% 为玩家 Y=377 / 232。32 区块视距，5 区块模拟距离，1280×720，FOV 70，关闭垂直同步，帧率设置 260。
- (-500, Y, -450) → (500, Y, 450) → 原起点；30 m/s，视角朝移动方向，俯仰角 0。
- 每轮使用相同初始世界模板的独立副本，静止预热 90 秒，采集一次完整约 89.7 秒的往返；一次只启动一个基准游戏。
- 打印关闭，参数保留 0 / 0 / 0。这里测试移动查看投影，不代表实际打印吞吐。
- 正式对照均记录 GC 日志，不开 JFR；正式采样期间没有编译或专项检查。正式四轮的顺序为基线 65%、修正版 65%、基线 40%、修正版 40%，之间有开发和被淘汰方案的检查。
- 平均 FPS 为帧间隔均值的倒数；1% Low 为最慢 ceil(N×1%) 帧平均间隔的倒数。分位数线性插值。最差 5 秒窗口按 1 秒步长在路线内滑动，按窗口记录帧数计算。
- 间隔来自客户端渲染循环，非显示器呈现时间。统计筛选 `diagonal_outbound` / `diagonal_return` 阶段；个别原始 `result.json` 总计数包含一帧 `stationary` 过渡帧，`summary.json` 同时保留筛选帧数与原报告帧数。
- 每高度每版仅一轮正式对照，没有随机交错复测或置信区间；不能外推所有世界、硬件或其他渲染器组合。

## 尖峰诊断

先对最新基线在 65% 高度做了一轮独立 JFR 诊断，不纳入正式性能表。148 个超过 33.3ms 的帧中，103 个与 GC 暂停存在超过 0.1ms 的时间重叠；19 个超过 50ms 的帧中有 17 个与 GC 暂停重叠。时间对齐使用采样开始 UTC 时间与逐帧间隔，存在亚帧级时间边界误差；相关不代表 GC 是每个尖峰的唯一原因。

同一诊断中，渲染线程采样大量落在原版地形视野裁剪、区段遍历和光照就绪查询。投影准备、构建和绘制之外的成本不可忽略。因此本轮没有通过缩减投影内容或降低视距来换帧率。

## 最终保留的修改

仅修改 1.20.1 审查层的 `TerrainLayerIndexMixin`：

1. 在原版重建流程前筛选需要重建的区段，减少未变化区段进入创建位置对象的循环。原版光照、重建方式、上传和顺序规则继续执行。
2. 在原有地形索引遍历中同时记录包含方块实体的区段，方块实体绘制阶段复用该列表，避免再次遍历大量空区段。
3. 无普通地形模型、只有方块实体的区段单独保留；每帧重新索引，结束后释放引用。源可见列表和遮挡判断不变。

原版渲染器专用路径：已有的 Sodium / Iris / Canvas / VulkanMod 检测会关闭整个索引 Mixin；本轮未在这些组合中实测。没有改动服务器逻辑、存档规则或投影精度。

## 被淘汰的尝试

- review.5 尝试 128 格分组视锥缓存。虽然约 163 万次原版等价比对通过，但真实 65% 路线只有 65.05 FPS，P99 50.01ms，>50ms 帧数 59，明显退步，已从源码撤回。
- review.6 将分组表换成数组；等价比对通过，但独立密集区段计时约 2.08ms，原版约 1.42ms。该小测试不能预测真实游戏收益，但足以否定这个方案的预期，未继续游戏压测，已撤回。
- 上述版本的代码快照、构建包与检查记录在本地保留，不随本目录发布。数据包保留 review.5 的真实游戏失败记录；review.6 仅做独立计时，没有游戏对照数据。

## 验证与限制

最终 review.7 构建成功。真实 Minecraft/Mixin 环境中的 22 项索引检查通过，覆盖五种地形层顺序与逆序、方块实体专用区段、脏标记变化、下一帧更新和引用清理；真实游戏完成两个高度的往返。

65% 固定视角预热截图完全一致；40% 结果见 `visual-checks.json`。这是固定视角核对，不能替代所有方块实体和其他模组组合的视觉验收。

核心代码未改动，没有额外重跑整套核心测试。GC 总耗时仍需关注：

- 65%：GC 累计耗时 3348 → 3476ms；可见分区就绪率 99.789% → 99.846%。
- 40%：GC 累计耗时 3303 → 3281ms；可见分区就绪率 99.651% → 99.859%。
