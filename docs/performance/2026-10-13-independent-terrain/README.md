# 独立原生地形管线：review.24

此页保留当时的实现和验证边界。后续已替换可见区块遍历，并重新做游戏对照；最新记录见 [可见区块遍历与 Sodium 对照](../2026-10-13-visibility/README.md)。

本轮仅修改 Minecraft 1.20.1 覆盖层，按 Sodium 0.5.13 的后台构建、区域存储、批量绘制思路独立实现；没有复制其源码或内嵌 Sodium JAR。此记录是实现说明，不是性能测试结果。

## 已接入的流程

1. Minecraft 提供区块区域快照及模型、流体、光照适配；重建工作进入本模组专用线程池。按逻辑处理器数量选取 1–6 个工作线程，并保留一个额外构建缓冲用于上传重叠。紧急更新也不在渲染线程上执行完整模型构建。
2. 工作线程在原构建缓冲内转换区域坐标，不复制一份完整网格。任务在创建时捕获不可变坐标和版本；上传与发布时再次核对。排序任务关联已发布网格的版本，不能拿旧排序结果覆盖新网格。
3. 一个区域为 128×64×128 格。区块顶点分配到共享顶点页；透明索引单独分配索引页。容量以顶点/索引为单位，显存字节计算使用长整数，避免重复乘步长造成异常分配。
4. 上传以最多 256 KiB 为一步，按帧继续。后台目标预算为 2 ms / 4 MiB，上一帧可见列表有尚未发布的区段时为 6 ms / 8 MiB。单次驱动调用、显存分配和完成回调不能抢占，因此预算不是严格的帧时间上限。
5. 不透明层按区域和缓冲页批量提交。透明层只合并原顺序里连续、兼容的绘制段，保持区段顺序与区段内的四边形排序。继续使用原版层状态、雾、光照纹理和资源包着色器。
6. 网格或透明索引替换后，旧范围通过 GPU fence 延迟回收；轮询不阻塞等待 GPU。空区段句柄不创建顶点、索引或 VAO 对象。退出世界、重载和关闭渲染器时清理区域资源。

绘制索引仍逐帧刷新；同一帧内各层共用检查结果，不再每层完整核对一遍来源数组。可见性继续使用 review.23 的原版等价规则。

## 与 Sodium 0.5.13 的区别

| 环节 | 此实现的选择 |
| --- | --- |
| 调度与存储 | 独立工作线程、带版本的上传队列、本项目区域分配器与批量提交 |
| 顶点格式 | 保留 Minecraft 的 32 字节格式与资源包着色器；没有实现 Sodium 的 20 字节编码 |
| 网格生成 | 调用 Minecraft/Fabric 模型、流体和光照适配；没有重写 Sodium 的模型渲染器 |
| 可见性 | 保留原版等价采样；没有重新加入此前风险较高的角度裁剪 |
| 透明处理 | 保留原版排序，并限制合批不改变透明顺序 |
| 其他优化 | 没有复制 Sodium 的实体、粒子、纹理、驱动补救及设置界面 |

因此，本轮完成的是一条可接入游戏的独立地形传输/绘制管线，不能称为 Sodium 0.5.13 的完整等价实现，也不能据此声称接近或超过 Sodium。

## 共存和验证边界

检测到 Sodium、Iris、Canvas、VulkanMod、OptiFabric，或指定 `-Dbetterlitematica.disableTerrainOptimizations=true` 时，整组地形入口均跳过；投影自身的后台构建不受影响。

用户提出本轮不再测试之前，中间实现完成了生产 JAR 的 13 个 Mixin 加载/跳过检查，以及离屏 GL 缓冲与透明顺序检查。之后增加了专用线程池、构建缓冲数量限制和分段上传；这些最终改动只做源码复核和编译打包，没有重跑测试，也没有启动游戏或做路线压测。中间结果不能当成最终版本的运行验收。

测试实例里的 Sodium 不在本轮自动停用；要体验新原生地形管线，需在退出游戏后停用外部 Sodium 并换入本轮 JAR。保留 Sodium 时，地形继续由 Sodium 接管。
