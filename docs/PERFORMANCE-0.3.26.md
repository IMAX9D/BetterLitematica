# 0.3.26：投影渲染和区段解码优化

## 修改

- `PackedSection` 在创建/后台解码时派生 4096 位的非零单元索引，渲染线程按原 YZX 顺序跳过 canonical air；其他空气状态继续检查。坐标、旋转、镜像、分层、模型随机种子和面剔除算法不变。新增索引包含在 CPU 缓存计费中；不写入 BPC，不改变源文件、缓存格式或完整材料直方图。
- `BlueprintCache.read` 仅在读共享文件游标时持锁，解压、CRC 和调色板校验在已有的两个后台线程中并行。没有增加线程数量；关闭、取消、请求代际校验保留。
- `SectionStreamer` 成功解码结果在队列满时等待消费，避免丢弃后重读。上限为 16 个待消费区段加 2 个线程本地结果；等待发生在后台线程，可以取消。
- 同一个投影绘制期间只绑定一次着色器/纹理及公共投影矩阵/透明度，每个区段仅更新原来的模型视图矩阵，各网格部分直接绘制。GLSL、网格内容、深度、颜色、透明度、光源方块公告板、绘制顺序不变。
- 小区段每帧完成数量上限由 8 提高到 32，仍受原有的协作式 4 ms 构建预算和 2 MiB 上传预算限制。模型回调及 GPU 驱动调用无法硬抢占，不能把这个时间预算当作最坏帧耗时保证。

视距、候选区段上限、全向预热与保留规则均未下调：22 区块对应 352 格，最多 32768 个候选区段，32 MiB 解码缓存和 512 MiB 网格预算/摆放。
